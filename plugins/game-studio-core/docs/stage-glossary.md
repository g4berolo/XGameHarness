# 阶段矩阵：每一条用大白话是什么意思

`plan/stage.md` 里那 33 行的 **Sub-phase 名字是行话** —— `Walking Skeleton`、
`POC`、`ADR`、`MVP`、`pillars` 全在里面。这些词有存在的理由（它们在别处的文档、
提交信息、评审记录里被引用，人要拿着它们去搜文件），**所以不翻译、不替换**。

这份表补的是另一半：**同一条用不做这行的人也听得懂的话再说一遍。**
跟 GDD 的「读本」是同一个路子（D-112 / D-114）：不是取代正本，是正本的另一面。

## 谁在读这份表

**客户端（XGameHarness Studio）的总进度那一页。** 它按 ID 查这张表，
把白话贴在行话标题下面。

所以这份表**必须留在 harness 里，不能复制进项目**：

- sub-phase 的**种类**是 harness 定的（`plan/stage.md` 开头那句
  「harness 只规定 sub-phase 的种类」），那么「这个种类是什么意思」
  当然也归 harness
- 项目侧那份 `plan/stage.md` 是**项目自己的文件，harness 不覆盖它** ——
  把白话写进模板的话，已经接入的项目（它们的 stage.md 早就写好了）
  一个字都不会变，而那正是最需要这份白话的地方

## 怎么改

- **ID 必须跟模板 `docs/templates/stage.md` 里的对上。** 对不上的行客户端查不到，
  那一行就只显示行话 —— **不显示成「没有说明」**，只是没有多的那一句。
- 项目自己**增的行**（模板里没有的 ID）查不到，这是正常的：
  那是项目自己定的必过项，harness 不知道它是什么。
- 一句话说完。写成两句的那一刻，它就变成第二份文档了。

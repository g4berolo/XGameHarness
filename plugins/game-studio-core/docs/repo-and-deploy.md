# 仓库怎么摆、怎么部署 —— 接工作室服务器的项目

`project-contract.md` 答的是「一个项目该有哪些**文件**」。
这一份答另一个问题：**那些文件放在哪个仓里，服务器上要配什么。**

两个消费方：

- `/project-init` —— 新项目建完本地那套之后，照这份把仓库和服务器摆好
- 已有项目要接服务器时，照「顺序」那一节走

> **不接服务器的项目跳过这一整份。** 一个仓、一次 `git init`，
> `/project-init` 建的东西全在那个仓里，没有任何额外步骤 ——
> 那是完全正常的用法，不是「简化版」。

---

## 一、两个仓，各装什么

接了服务器之后是**两个仓**：

| | 装什么 | 谁在写 |
|---|---|---|
| **游戏工程仓** | `client/ art/ tools/ docs/ .claude/ CLAUDE.md .gitattributes …`<br>**不含** `plan/ design/ team/` | 程序、美术，正常 git |
| **文档仓** | 只有 `plan/ design/ team/` + `.claude/team.json` | **只有服务器**（客户端的改动由它代为提交）+ 管理员 |

客户端那边**看不见这件事**：程序员和策划一样 `git clone` 游戏工程仓，
那三个目录由客户端从服务器取回来放到同一个位置。
**它不是一条替代的取法，是同一条路上多出来的一层。**

### 为什么要拆

策划在客户端里点一下「这个任务完成了」，是**服务器**替他提交的
（单写者：一次一笔、按到达顺序，所以并发不存在）。

那些提交**不该落在游戏工程仓的历史里** —— 一个仓的历史是给人读的，
掺进几百笔「阶段状态：X → Y」之后就没人读得动了。

### 为什么是「文档仓」而不是「全仓搬到自建服务器」

搬的只是**开发中需要及时性、而且改得勤**的那部分。游戏工程仓照旧在原处，
LFS、CI、所有人的克隆都不动。

---

## 二、服务器上要配什么

```
名册里那条项目
  id      项目 id。**会被当成目录名**，只能用字母数字和 . _ -
  name    给人看的名字
  repo    游戏工程仓的地址  ← 客户端「拉项目」clone 这个
  docs    文档仓的地址      ← 服务器写和下发对着这个。**空着 = 跟 repo 同一个**

服务端环境
  XGH_WRITER_ROOT        每个项目一份稀疏工作副本放哪儿（几十 MB 一个）
  XGH_WRITER_GIT_USER    代码库上那个**专用账号**（不是某个人的账号）
  XGH_WRITER_GIT_TOKEN   只要 write，而且**只加进文档仓一个仓的协作者**
```

⚠ **`repo` 和 `docs` 必须分开填，这是踩出来的**：它们被一个字段喂过一阵，
于是服务器一直往名册没说的那个仓里提交 —— 提交成功、推送成功、
**日志一行错都没有**，三周没人发现。唯一看得出来的地方是手动去读
那份工作副本的 `origin`。

⚠ **`XGH_WRITER_ROOT` 是个会写盘的目录**。服务用 systemd 的
`ProtectSystem=strict` 跑的话，**不在 `ReadWritePaths` 上的路径进程根本看不见** ——
`mkdir` 报 `ENOENT`，看着像路径拼错了。

⚠ **文档仓要有异地备份。** 搬完之后那些文件只存在于服务器那块盘上 ——
单盘、没 RAID、没快照。盘坏了，切割之后的所有设计改动就没了。
定时 `git push --mirror` 到另一个**没人克隆的**备份仓就够
（`--mirror` 会让目标跟源完全一致，源上没有的引用会被删掉，
所以**别把那个地址指向任何有人在用的仓**）。

## 三、顺序（不许颠倒）

**先有得拿，才能删。** 反过来做的话，那段时间里谁都拿不到那三个目录。

1. **建游戏工程仓**，正常 clone 到本地
2. **`/project-init`** 在本地把该有的文件建全（`project-contract.md` 那份清单）
3. **首次提交推上去** —— 这时候 `plan/ design/ team/` **还在游戏工程仓里，
   这是对的**：它们得先有一个起点
4. **建文档仓**，把那三个目录搬进去（见第四节）
5. **配服务器**：名册那条（`repo` + `docs`）、写入令牌、备份定时任务
6. **验一次下发真的通**：客户端打开项目，那三个目录的内容真的从服务器落下来
7. **最后**才从游戏工程仓里把它们去掉（见第五节）

第 3 步和第 7 步之间那段**两边都有** —— 是重复，不是丢失。
**这段时间越短越好，别让它跨周**：重复期间游戏工程仓里那份是只读的旧账，
谁都可以继续改它，但那些改动不会流到文档仓那份上。

---

## 四、把那三个目录搬进文档仓

**新项目**（第 3 步刚推完，没什么历史）：建一个空仓，把那三个目录第一次推进去就行。

**已经跑了一阵的项目**（想保住历史）：用 `git filter-repo` 从游戏工程仓切一份出来，
只留那三个目录。

⚠ **切的时候别忘了带上 `.claude/team.json`。** 它不在那三个目录里，
但**下发要用它认人**（便条收件箱靠它把 git 身份对到名册上的人）。
漏了的话，全队的便条那一页同时认不出人，而屏幕上只会说「没有这份名册」。

⚠ **那三个目录里不许有 LFS 文件。** 文档仓通常没配 LFS，于是那些文件在
新仓里只是一份**指针文本** —— 下发出去的不是表格，是一行 `version https://git-lfs…`，
**而它看起来完全正常**。搬之前先查一遍：

```bash
git lfs ls-files -n | grep -E '^(plan|design|team)/'   # 应该一条都没有
```

## 五、从游戏工程仓里去掉

### 先证明不丢东西

**逐个 blob 比一遍两边**，不是比磁盘上的文件：

```bash
# 两边各来一份，然后 diff
git ls-tree -r <游戏工程仓的分支> -- plan design team | awk '{print $3, $4}' | sort
git ls-tree -r <文档仓的分支>     -- plan design team | awk '{print $3, $4}' | sort
```

⚠ **比 blob sha，别比文件内容**：Windows 检出会把 LF 变成 CRLF，
照文件比的话一百多个全红，而数据一个字节都没坏。

⚠ **两边的 `core.quotePath` 可能不一样**，中文文件名一边是原文一边是
`\346\210\227` —— 那也是写法的差别，不是内容的差别。

### 然后

```bash
git rm -r --cached plan design team     # ⚠ --cached：本机磁盘上那份留着
```

**为什么要 `--cached`**：不留的话，这台机器上还没升级的客户端当场没东西可读。
别人 `pull` 的时候 git 会删掉他们的（那是这一步的本意），
所以**装上带下发的那个版本之前别 pull**。

**`.gitignore` 要跟着加**，否则每个人的 `git status` 上永远挂着一百多个 `??`，
而且迟早有人手滑把它们再 `git add` 回去：

```gitignore
# 设计文档由工作室服务器下发，不进这个仓
plan/
design/
team/
```

**提交信息要写给撞上这件事的程序员看**：文件去哪了、怎么拿回来、
不用客户端的话去哪儿找。他第一反应会是「谁把设计文档删了」。

## 六、`.claude/team.json` 有两份，**文档仓那份说了算**

它同时在两个仓里：游戏工程仓那份是**新克隆的起点**，文档仓那份是**正本**。

客户端**一条写回它的路都没有**，而且本地改过会被服务器那份**盖回去**
（跟别的文件正好相反 —— 别的文件本地改过就留着并说出来）。
理由是：留着等于让那台机器认一份跟别人不一样的名册，
**而没有任何地方会说它不一样**。

所以**改名册要改文档仓那份**。改游戏工程仓那份没用，下一次下发会盖回去。

> `team.json` 里本来就写着角色（`admin` 的 `can_edit_team_config: true`）——
> 上面这条是把那句话变成结构性的，不是另立一套说法。

- [ ] 那三个目录里**一个 LFS 文件都没有**

- [ ] `XGH_WRITER_ROOT` 配了，而且进了 systemd 的 `ReadWritePaths`
- [ ] **验过一次**：客户端打开项目，那三个目录真的从服务器落下来

# 任务执行类型与最小状态单元

适用于Sprint、里程碑拆解、backlog、返工清单及临时任务。AI可执行工作与必须人工完成工作分开记录，是Harness的流程原则，如同GDD原文与人工读本各司其职；不是把同一工作复制成两套状态。

## 标签与分类

- 每条可执行任务的Task标题必须以且仅以一个标签开头：`[AI]`或`[HUMAN]`。ID列保持原始ID，标签不塞进ID；优先级与执行类型是两件事。
- [AI]：当前宿主实际具备工具、权限和输入，可由AI执行且以明确证据独立验收。不能因为Owner写了某个agent就默认可自动执行；Computer Use也只有实际具备能力和授权时才算AI执行。
- [HUMAN]：必须由真人完成的操作、主观评审、批准或决策。写明真实负责人；尚未确定时写“待指定”，不得捏造身份。AI可以准备材料，但不能代替人签署结论。
- 能力不明先核实；仍无法确认的部分拆为[HUMAN]“确认执行方式/补充必要输入”，后续实现列出该依赖，不伪称已经具备执行能力。

## 一个任务一个可独立完成的结果

禁止“完善山体模型与走向，并获得人工审核通过”这样混合制作和批准的任务。每行只有一种执行类型、一名负责执行的Owner、独立验收条件及对应DoD。不同Owner、独立交付或独立验收的步骤也应拆开。

例如（假设AI已具备相应建模和引擎工具）：

| ID | Task | Agent/Owner | Est. Days | Dependencies | Acceptance Criteria | Status |
|----|------|-------------|-----------|-------------|-------------------|--------|
| S3-001 | [AI] 完善指定区域山体模型与走向 | AI执行角色 | 待估 | 已确认的地形设计 | 提交指定资产/关卡版本；给出轮廓对比与技术检查证据 | Not Started |
| S3-002 | [HUMAN] 审核该区域山体轮廓与走向 | 待指定 | 待估 | S3-001 | 真人针对指定版本记录通过或修改意见 | Not Started |
| S3-003 | [HUMAN] 手工雕刻必须人工处理的局部细节 | 待指定 | 待估 | S3-002 | 保存修改资产并记录范围与版本 | Not Started |

S3-001的DoD不得包含S3-002的批准；S3-002也不能重复包含S3-001的制作。若实际工具无法制作某部分，则该制作步骤本身标[HUMAN]，不能硬分给AI。

## Sprint编排与状态

- Tasks下的Must Have / Should Have / Nice to Have放AI任务；最后单设`### Human Actions & Review`（人工操作与审核）集中列人工项，仍使用同一任务表列及独立ID。人工项在Task中注明必要/可选或优先级，不能因位于末尾而被降为可选。
- 人工终审通常安排在Sprint末尾；前置授权、输入、人工制作按真实依赖及时执行，不能为了排版延后。AI可先完成不依赖它的工作，遇到真实依赖才阻塞。
- Definition of Done分别列`### AI Execution`和`### Human Actions & Review`，每条复选框以完整任务ID开头；[ ]未完成，[~]部分完成，[x]本任务全部验收通过。Task与DoD各一份，不在末尾重复抄一遍任务制造双重真相源。
- AI任务有充分证据时可[x]，关联人工任务保持[ ]；不要因人工尚未审核把已完成的AI任务标成“部分完成”。反过来，AI全部完成不等于Sprint/里程碑已完成，必要人工任务未完成时总体验收仍待完成。
- 人工任务的[x]必须来自可追溯的真人操作/批准证据（人、时间、目标版本、结论）；AI自评、自动测试、无回应均不等于人工批准。源码测试、实际引擎运行和真人视觉评审分别记录。
- 审核要求修改时新建带标签的返工任务，关联原制作任务与审核任务；旧完成证据保留，审核项待复核。若旧完成判定本身错误，则据证据纠正并保留更正原因，不能为了通过审核静默重写历史。
- 状态汇报分别给出AI完成/总数、人工完成/总数、待人工的ID与负责人、阻塞的后续任务；没有某类任务时标“不适用”，不编造100%。

## 既有计划迁移

仅在用户授权修改的项目/计划范围内应用；Harness升级不批量重写项目计划。保留旧ID、文件名、证据和引用。拆分混合任务时，原ID保留为父项/历史索引，新增稳定子ID，记录旧新映射；父项不再作为可执行任务重复计数。既有完成标记不自动继承到新人工任务；依据原证据重新判断各子项。缺失人工证据保持未完成，不批量补勾。

# XGS 插件警告：项目目录关联排查

日期：2026-10-16。结果：修正本机目录关联后，用户确认警告消失。

## 出现过的问题

1. 用户在 XGS 打开 CivTerrainLab，但本机台账把该项目关联到 `D:/work/GameStudio/XGS-Test`。旧目录缺少 `.claude/settings.json`，因此 XGS 正确地对错误目录报出“没有启用任何插件”。重启仍读取旧关联，不能解决问题。
2. 排查最初误把当前 Codex 工作区 `xHD2D_Test_UE5` 当成 XGS 项目，给该工作区补配置后，用户看到的错误没有变化。应先核对实际项目，不能从当前工作目录推断另一应用的目录。
3. 当前 Codex 会话能看到技能，不能证明 XGS 能加载插件。XGS 的两个引擎都通过项目检查读取启用声明；不能把警告简单认定为 Claude/Codex 不兼容造成的误报。
4. 已有会话回放旧检查结果只是可能原因。在核对日志与项目关联前，不应把缓存作为结论。本次真正原因是目录关联错误。
5. Codex 初始化脚本此前不生成 XGS 所需的启用声明。这是独立缺口，已修复为 init/sync 在文件缺失时创建配置，按选定 pack 声明 enabledPlugins。合并远端时保留上游完整配置模板和名册流程；已有配置完整保留。

## 下次按这个顺序检查

1. 先取得用户要打开的绝对路径；区分项目显示名、当前任务工作区与 XGS 实际目录。
2. 核对 XGS 日志最新 `[open]`、项目列表的本机路径、`~/.xgh/projects.json` 中该项目的 `dir`。日志只有目录末级名时，用台账和用户路径共同确认。
3. 用 XGS 的 inspectProject 对目标绝对路径检查插件、命令和 warnings。检查实际配置的 JSON、enabledPlugins、重复键，以及插件目录是否存在。
4. 路径关联错误时，先备份台账，仅修改用户确认的项目记录，保留其它项目。不要给错误目录补配置来消除警告。
5. 目标路径正确且配置确实缺失时，才补配置；已有权限和显式禁用项不覆盖。
6. 重新从项目列表打开正确项目并新建会话。旧会话绑定和回放不会因为修改台账而自动迁移。
7. 分别记录文件检查、解析器检查和用户界面确认。源码测试通过不等于运行中的安装包已更新，不等于界面问题已经解决。

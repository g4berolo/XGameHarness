# 把读本搬出去

一篇 GDD 里还留着 `## 读本`（2026-09-14 之前写的都是这样），
把它原样搬到 `design/digest/<跟 GDD 同名>.md`。

**为什么要搬**：做开发的 agent 读那篇 GDD 是为了规则表，而读本是白话 ——
在一个文件里，它每次都跟着进上下文（实测占一篇的 37%）。
理由的全文在 `rules/design-docs.md` 的「读本住在哪儿」。

## 这是一次搬家，不是一次重写

> **一个字都不许改。**

搬家和重写混在一起做，是这个技能唯一会造成真损失的坏法：用户在 diff 里
分不出哪些是搬过去的、哪些是你顺手改的，而**改错了不会有任何地方报错**。

读的时候发现读本写得不对、缺了东西、跟规则对不上 —— **只报，不改**，
交回去的时候说出来，让用户决定要不要再跑一次 `/game-studio-core:write-digest`。

## 步骤

### 1. 读那篇 GDD，找到 `## 读本` 那一节

从 `## 读本` 那一行起，到**下一个 `## ` 标题**为止（不含）。中间的
`###` / `####` 小节都算在里面。

⚠ **围栏里的 `##` 不是标题。** 读本里可能有 markdown 示例，
撞上它就收工会切掉半节 —— 而少半节不会报错，只是屏幕上没了。

**没有这一节**：说一句「这篇的读本不在文档里」，然后停下。
先去 `design/digest/` 看看是不是已经搬过了，是的话说出来；
都没有就是这篇还没有读本，提示可以跑 `/game-studio-core:write-digest`。

### 2. 顺带把 `## 本篇用到的新词` 也带过去？——**不带**

那一节是 GDD 的约束载体之一（`rules/design-docs.md` 的「两档共有的三节」），
留在 GDD 里。客户端显示读本时会**同时**显示这两块，搬走反而少了一处。

### 3. 写新文件

`design/digest/<跟 GDD 同名>.md`，头三行是头部块，之后是原样搬过来的正文：

```markdown
# <跟 GDD 一样的标题> — 读本

> **文档**：design/gdd/<文件名>.md
> **写于文档的最后更新**：<原样照抄那篇 GDD 头部的 Last Updated>
> **最后更新**：<今天>

<这里开始是原样搬过来的读本正文，`## 读本` 那一行本身不要>
```

两件事要注意：

- ⚠ **`写于文档的最后更新` 原样照抄那篇 GDD 的 `Last Updated`**，
  不是今天。客户端拿这两个值比对，判「这份读本是不是写在文档上次改动之前」。
  写成今天的话，一份其实早就过期的读本会显示成「跟文档同步」—— 而且不报错。
  那篇 GDD 没写 `Last Updated` 的，值写 `未知`，并在交回去时说一句。
- **标题层级降一级**：原来读本里的 `###` 在新文件里还是 `###`
  （`## 读本` 那一行去掉，它下面的小节层级不动）。改层级 = 改内容。

**目录不存在就建**（`design/digest/`）。

### 4. 从 GDD 里删掉那一节

整段删掉，包括 `## 读本` 那一行。**删干净** —— 两个文件里各留一份，
走散的时候不会有任何地方报错，而这正是当初把读本放在文档里要防的事。

删完确认 GDD 的第一节是 `## 设计前提`。

### 5. 交回去的时候说三件事

- 搬了多少字，从哪个文件到哪个文件
- **读的时候发现的问题** —— 只报，不改
- 那篇 GDD 有没有 `Last Updated`（没有的话，客户端提示不了读本旧没旧）

## 不要做的事

- **不要顺手重写**，哪怕读本明显写得不好（上面那一节）
- **不要改 GDD 的别处**
- **不要一次搬一批**。一次一篇，用户在 diff 里看得清 ——
  批量搬的时候一处切错，混在几十个文件的改动里没人看得见
